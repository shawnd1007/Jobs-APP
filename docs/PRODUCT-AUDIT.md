# Jobs app product audit

The app already has employer feeds, saved searches, résumé import, an alert inbox, a review checklist and application tracking. The next release should make those pieces serve one goal: find credible billing, reconciliation and revenue operations openings that fit your experience, then make it easy to decide what to do next.

| Priority | Current friction | Proposed change | How to check it |
| --- | --- | --- | --- |
| 1 | Jobs opens on Review Inbox, which can mix strong target roles with unrelated high scores. Several very different roles scored 100 in a prior run. | Make **For You** the default view. Rank role and responsibility fit first. Show matched skills, location eligibility, published base pay and the largest gap. Keep listings with unresolved pay or location in a review view. | Review the first ten results against a labeled set. Check that a role with a passing mention of billing stays below a genuine billing role. |
| 2 | Résumé skills improve job scores. Alert criteria live in separate saved searches. | Put target roles, skills, location and pay in a short **Search Profile**. Let users preview which saved searches a change would affect and choose whether to update them. | Import a résumé, select skills and preview why an existing listing moves up. Confirm the selected changes appear in the intended saved search. |
| 3 | Cards put pay and a numeric score on the same line. Posting age, verification and the reason for a match take extra taps. | Give every card a consistent order: title, employer, work location, base pay, posting age and one short match reason. Put pay on its own line. Use clear labels for missing pay, geographic pay tiers and stale checks. | Check long titles, missing pay, dark mode and large text on an iPhone. Each result should be understandable at a glance. |
| 4 | The bucket picker is the main way to move through the job workflow. Alerts live inside Search and employer boards have a top-level tab. | Give **Saved**, **Applied**, **Interviews** and **Archived** a dedicated **My Jobs** area. Add quick Save and Pass actions with Undo. Keep a follow-up date and the last action visible. Move feed administration into Settings. | Save a listing, return to it, record an application and schedule a follow-up from the phone. |
| 5 | Notifications arrive when the app checks the Mac. The backend needs a reachable local server. | Verify a signed physical iPhone build, onboarding, connection recovery and the full application flow. Add authenticated access before wider use. Evaluate push delivery after the core experience is stable. | Repeat the full flow on a physical phone and check behavior when the Mac is asleep or unreachable. |

Indeed provides a familiar search, alerts and application tracking workflow. This app can make that workflow more personal by showing the evidence behind a match and keeping the next action in view. [Indeed My Jobs](https://support.indeed.com/hc/en-us/articles/205332490-What-is-My-Jobs) · [Indeed job alerts](https://www.indeed.com/help/job-seekers/articles/204488890-starting-stopping-and-managing-job-alerts?hl=en&co=US)

For the first design pass, add an app icon, use consistent spacing and typography, and make **Save** and **Open Employer Posting** easy to reach. Use the existing teal accent and native iOS controls. Measure the share of the first ten jobs worth saving, the share with clear pay and location evidence, and how long it takes to find the first job worth acting on.

This audit covers the SwiftUI and backend source, earlier simulator observations and prior search results. The live dashboard did not respond during this review, so there is no fresh count of match scores or pay coverage.
