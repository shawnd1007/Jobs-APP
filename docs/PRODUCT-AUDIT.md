# Early iPhone product audit

This historical audit records design issues from the first native prototype. Use the [approved vision](PRODUCT-VISION.md) for product goals, the [Build 9 checklist](STAGE-TWO.md) for delivered work, and the [roadmap](NEXT-STEPS.md) for current priorities.

| Area | Early friction | Design response | Acceptance evidence |
| --- | --- | --- | --- |
| Discovery | A general review inbox mixed different kinds of matches. | Separate recommendations from opportunities with unresolved pay, location, or posting evidence. | Compare the first ten results against a fictional labeled set. Test that a passing keyword mention ranks below direct responsibility evidence. |
| Profile | Profile changes and saved search criteria were easy to confuse. | Give the profile a clear home, with an explicit preview before applying its choices to a saved search. | Save fictional résumé skills and confirm that only the intended search changes. |
| Listing cards | Pay, recency, verification and match reasoning took several taps to find. | Give title, employer, location, pay, evidence and the next action a consistent order. | Check long titles, unknown pay, dark mode, and large text. |
| Tracking | Review categories and application stages competed for attention. | Give saved roles, applications, interviews, and follow-ups a dedicated workspace. | Save a fictional role, record an application and follow-up, then verify the history after refresh and reconnect. |
| Device reliability | Search and alerts depended on reaching the Mac. | Preserve a readable last-synced copy and test connection recovery. | Repeat the workflow on a signed phone and record what works when the backend is unavailable. |

The audit used familiar job search and tracking patterns as reference points. Jobs adds personalized explanations and direct employer evidence.
